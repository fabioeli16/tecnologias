En Python, un modelo de ejecución describe cómo, cuándo y bajo qué mecanismo se ejecuta un programa. No es una única característica de Python; depende de cómo diseñes y despliegues la aplicación.

Para tu caso de automatización que monitorea varios endpoints SOAP, es especialmente importante elegir el modelo adecuado.

Principales modelos de ejecución en Python
Modelo						¿Cómo funciona?											Ejemplo
Ejecución única				El programa inicia, hace su trabajo y termina	python main.py
Proceso continuo			El programa permanece ejecutándose y realiza tareas periódicamente	Monitor de endpoints cada 60 segundos
Programado (Scheduler)		Se ejecuta en determinados horarios o intervalos	cron, APScheduler
Bajo demanda / API			El programa espera peticiones HTTP y ejecuta una acción	FastAPI / Flask
Multihilo (Threading)		Varias tareas pueden ejecutarse concurrentemente usando hilos	Consultar 20 SOAP simultáneamente
Asíncrono (AsyncIO)			Maneja muchas operaciones de I/O concurrentemente mediante async/await	Muchas llamadas HTTP simultáneas
Multiproceso				Utiliza varios procesos independientes	Tareas intensivas de CPU
Event-driven				El código reacciona a eventos o mensajes	RabbitMQ, Kafka, Redis

+FUNDAMENTOS DEL INTERPRETE DE PYTHON

---------------------------------------------------------------
-PIPELINE DE EJECUCION DE CODIGO PYTHON
Escribes código Python (.py)
CPython lo compila a bytecode
La PVM (escrita en C) interpreta ese bytecode y lo ejecuta


---------------------------------------------------------------
-CPYTHON Y LA PVM (Python Virtual Machine)

CPython es la implementación de referencia de Python: el programa completo que instalas cuando descargas Python desde Python Software Foundation. Está escrito principalmente en C.

Incluye varias piezas importantes:
el compilador que transforma .py en bytecode
la gestión de memoria (incluido el recolector de basura)
las bibliotecas estándar
el intérprete interactivo
y la PVM (Python Virtual Machine)
La PVM no es algo separado de CPython. Es solo una parte interna de CPython: el mecanismo que ejecuta el bytecode instrucción por instrucción.

Una analogía útil:
Si CPython fuera un computador completo,
la PVM sería más parecido a la CPU


---------------------------------------------------------------
-Manejo de memoria

CPython usa principalmente:

Conteo de referencias
Garbage collector adicional (para ciclos)


---------------------------------------------------------------
Tipado dinámico y objetos

En CPython:

Todo es un objeto
Las variables son referencias, no cajas de datos

-MULTI-THREAD VS MULTI-PROCESING

Diferencia clave
Característica	Multithreading	Multiprocessing
Memoria	Compartida	Separada
GIL	Sí afecta	No afecta
Rendimiento CPU	Limitado	Alto (paralelismo real)
Comunicación	Fácil	Más compleja
Uso ideal	I/O	CPU intensivo

Regla práctica
Si tu programa espera cosas → usa threads
Si tu programa calcula cosas → usa processes
